# Visual degradation breaks a fine-tuned VLM but not a frozen self-supervised encoder

Code and results for the IEEE MIT URTC 2026 paper *Visual Degradation Breaks a
Fine-Tuned Vision-Language Model but Not a Frozen Self-Supervised Encoder: A
Robustness Study for Roadway Flood Monitoring*.

Kunal Chevuri, Prosper High School, Texas.

## What the study does

Roadway flood classifiers are validated on clean photographs, but a traffic
camera in a storm produces blurred, dark, noisy frames. This study takes two
flood-severity classifiers trained on the same real data and re-scores them on
the same held-out photographs after four perturbations: Gaussian blur, reduced
brightness, additive pixel noise, and all three applied at once.

The two models are built on opposite principles:

| | Adaptation |
|---|---|
| **SmolVLM2-2.2B** | QLoRA fine-tuning, rank-8 adapters on the language-side attention projections |
| **I-JEPA ViT-H/14** | frozen encoder, three-class logistic regression on mean-pooled patch tokens |

The headline results, all macro-recall on the same 238 real held-out images:

- The fine-tuned VLM falls from **67.8%** clean to **34.4%** under all three
  degradations. Chance on three classes is about 33%.
- Its recall on the most severe flood class goes to **0.0%**: every severe-flood
  image in the test set is labelled "no flood".
- The combined result is lower than any single perturbation predicts. Blur alone
  leaves 54.2%, darkness 64.1%, noise 41.5%. The damage compounds rather than
  adding.
- Under noise, the only condition both models were run through, the frozen
  encoder does **not** fall: 54.8% clean to 58.7% noisy, against the fine-tuned
  model's 26.3-point drop.

Because every condition scores the same model on the same images, conditions can
be compared image by image rather than by their averages. `run_urtc_significance.py`
runs McNemar's exact test on those paired outcomes.

## Layout

```
run_combined_degradation.py       blur + dark + noise applied simultaneously (needs a GPU)
run_ijepa_robustness_noise.py     frozen I-JEPA probe under additive noise
run_urtc_significance.py          paired McNemar tests across the five conditions
plot_urtc_figures.py              the five-panel degradation strip
plot_urtc_robustness.py           per-class recall and robustness bars
results/                          per-image predictions for every condition
splits/                           the 30% real-data train/test partition
reference_baseline_results/       the 104-image synthetic label manifest
figures/                          generated figures as they appear in the paper
```

## Reproducing

The analysis runs on CPU in seconds, because the per-image predictions for every
condition are committed under `results/`:

```bash
pip install -r requirements.txt
python run_urtc_significance.py     # McNemar tests, reproduces the paper's p-values
python plot_urtc_robustness.py      # per-class recall and robustness figures
```

Re-running the perturbation experiments themselves needs a GPU, the
SmolVLM2-2.2B QLoRA adapter, and the image data:

```bash
python run_combined_degradation.py
python run_ijepa_robustness_noise.py
```

### Data and artifacts not in this repository

- **STURM-FloodDepth** real flood photographs. A public dataset by its original
  authors, cited in the paper; not redistributed here. `run_combined_degradation.py`
  expects it at `data/sturm_flooddepth_real/upscaled_images/Level*/`.
- **The synthetic flood images** are released separately at
  [10.5281/zenodo.23251071](https://doi.org/10.5281/zenodo.23251071) under CC BY 4.0.
- **I-JEPA embedding cache** (`ijepa_embeddings/embeddings_cache.json`), a derived
  artifact regenerated by the embedding step rather than committed.
- **The QLoRA adapter** (`adapters/blend_30pct`), a training output.

`plot_urtc_figures.py` writes into `overleaf_urtc/figures/`, the paper's LaTeX
tree. Copies of what it produced are in `figures/`.

## Scope

The paper states its limits and they apply to this code. Noise is the only
condition both models were run through, so the cross-model comparison covers one
of the three perturbation components. Each condition uses one trained copy rather
than seed-averaged results, perturbation severity is fixed rather than swept, and
the training mix is 30% real data, which is not the optimum for either model. The
absolute numbers are bounded by those choices. The comparison between conditions
is not, because every condition scores the same trained model on the same images.
